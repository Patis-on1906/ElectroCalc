# ElectroCalc — расчёт электрических цепей DC/AC

WPF-приложение для построения электрической схемы и пошагового анализа цепей.

Основные режимы решения: МКТ, МУП/MNA, запись законов Кирхгофа, метод эквивалентного генератора и данные потенциальной диаграммы. Для AC на текущем этапе подключены МКТ и МУП.

## Требования

- Windows 10/11;
- .NET 8 SDK;
- Visual Studio 2022 / Rider.

```bash
dotnet restore
dotnet run
```

## Как теперь строится расчётный граф

Провода являются идеальными соединениями и объединяют свои концы в один электрический net. Затем точки, в которых последовательно соединены ровно две ветви, автоматически сворачиваются.

Например, цепочка

`узел A — R1 — провод — R2 — узел B`

создаёт **одну расчётную ветвь A→B с элементами R1 + R2**, а не дополнительный узел между R1 и R2.

Существенными узлами остаются точки разветвления (обычно 3 и более ветвей) и необходимые граничные точки. Для простого кольца автоматически выбираются только две опорные точки, чтобы не создавать узел между каждым элементом.

## Поддерживаемые элементы в DC

- `R` — сопротивление;
- `E` — источник ЭДС, внутреннее сопротивление учитывается последовательно;
- `J` — идеальный источник тока; при последовательном включении задаёт ток всей ветви;
- `C` — в установившемся режиме постоянного тока считается **разрывом**;
- `L` — в установившемся режиме постоянного тока считается **коротким замыканием**.

Для направления ветви используется единое соглашение:

`U = φstart − φend = R·I + E`.

Полярность каждого источника корректируется с учётом того, совпадает ли направление ветви с визуальным направлением PortA→PortB элемента.

## Что исправлено

- расчётный граф полностью пересобирается из логических соединений проводов и больше не зависит от координат/порядка рисования;
- последовательные элементы объединяются в одну ветвь;
- перемещение уже подключённых элементов не разрушает связь графа;
- исправлены знаки ЭДС в МУП;
- исправлены взаимные коэффициенты и знаки ЭДС в МКТ;
- добавлена обработка идеальных источников тока в МКТ через дополнительные ограничения;
- идеальные источники напряжения и нулевые сопротивления рассчитываются через MNA;
- исправлена обработка C и L в DC;
- исправлен расчёт и знак мощности источников;
- метод Тевенина использует тестовый источник тока 1 А для вычисления Rэкв, что корректно работает и при Rэкв = 0;
- после расчёта ток каждого элемента отображается с учётом его собственной ориентации;
- выбранная ветвь нагрузки сохраняется при пересборке графа;
- результат автоматически инвалидируется после изменения схемы или параметров;
- мощность в таблице показывается со знаком: `+` потребление, `−` генерация;
- точку соединения можно выбрать ПКМ и удалить.

## Быстрая проверка

### Тест 1 — источник напряжения и резистор

Две ветви между одними узлами:

- `E1 = 10 В`, идеальный;
- `R1 = 5 Ом`.

Ожидается: `|I| = 2 А`, `U = 10 В`, мощность резистора `20 Вт`, мощность генерации источника `20 Вт`.

### Тест 2 — последовательная ветвь

Две ветви между двумя узлами:

- ветвь 1: `E1 = 10 В` последовательно с `R1 = 1 Ом`;
- ветвь 2: `R2 = 4 Ом`.

Ожидается: **2 расчётных узла, 2 ветви**, ток по модулю `2 А`.

### Тест 3 — источник тока

Две ветви между двумя узлами:

- `J1 = 2 А`;
- `R1 = 5 Ом`.

Ожидается: напряжение по модулю `10 В`, ток резистора `2 А` противоположно направлению источника, баланс мощности `20 Вт`.

## Примечание

Приложение сохраняет полностью рабочий установившийся режим **постоянного тока** и содержит первый этап синусоидального AC-анализа через комплексные МУП/МКТ. Переходные процессы во временной области пока не реализованы.


Подробный разбор причин и исправлений находится в `TECHNICAL_ANALYSIS.md`.

## Сохранение и открытие схем

Схема сохраняется в собственный открытый формат `*.ecircuit.json`. Это обычный JSON,
который содержит элементы, их параметры и положение на холсте, точки соединения,
логические концы проводов, выбранный метод расчёта и ветвь нагрузки метода
эквивалентного генератора. Расчётные узлы и ветви намеренно не сериализуются:
после открытия они заново строятся из схемы тем же алгоритмом, который используется
перед расчётом.

Текущая версия формата: `2`. Поле `Format` имеет значение `ElectroCalcCircuit`.
При открытии выполняется проверка версии, GUID объектов, числовых параметров и всех
ссылок проводов. JSON можно хранить в системе контроля версий и при необходимости
просматривать вручную.

## v5 — системы Кирхгофа и символический вывод

- Добавлен отдельный режим «Законы Кирхгофа»: программа формирует N−1 независимых уравнений по первому закону и B−N+1 уравнений по второму закону в токах ветвей I1, I2, …, затем подставляет номиналы и выводит найденные токи.
- В МКТ сначала показывается символическая система, затем система после подстановки значений и сразу найденные контурные токи. Промежуточные шаги метода Гаусса скрыты.
- Баланс мощностей сначала выводится символически по отдельным E/R (и внутренним сопротивлениям источников), затем численно.
- Существенные расчётные узлы подписываются непосредственно на холсте как «Узел 0», «Узел 1», … .

## v6: МУП и общий вид законов Кирхгофа
- Режим «Законы Кирхгофа» теперь только формирует символические уравнения 1-го и 2-го законов без численного решения.
- В МУП базисный узел выбирается автоматически: сначала узел идеального источника ЭДС, затем узел максимальной степени, затем узел с наибольшим числом источников.
- Потенциалы, непосредственно задаваемые идеальными источниками ЭДС относительно базисного узла, исключаются из неизвестных.
- МУП выводится как: общий вид системы → система с числами → готовые потенциалы; шаги метода Гаусса скрыты.

## v9 — фундамент синусоидального режима AC

Добавлен выбор режима электрической цепи:

- `DC` — существующий установившийся режим постоянного тока;
- `AC` — синусоидальный установившийся режим с общей частотой схемы `f`.

В AC источники `E` и `J` задаются **действующим значением (RMS)** и начальной фазой в градусах. На холсте источник отображается как, например, `100 В RMS ∠30°`.

В ядро добавлена независимая от UI модель `CircuitAnalysisSettings` и универсальная комплексная модель ветви `SteadyStateBranchModel`. Для AC:

- `Z_R = R`;
- `Z_L = jωL`;
- `Z_C = 1/(jωC)`;
- `ω = 2πf`;
- напряжения и токи представлены `System.Numerics.Complex` как RMS-фазоры.

DC также описывается этой моделью как частный случай с чисто действительными источниками; правила `C=разрыв`, `L=КЗ` сохранены.

Добавлен комплексный метод Гаусса `ComplexLinearSystemSolver`. Публичные решатели МУП и МКТ теперь принимают настройки режима. В AC они используют комплексные MNA/МКТ-решатели и выводят токи и напряжения одновременно в прямоугольной и полярной формах. Проверенный DC-путь МУП/МКТ сохранён без изменения численной логики, чтобы не вносить регрессии на этом этапе.

В AC доступны **МУП, МКТ, законы Кирхгофа, метод эквивалентного генератора, расчёт P/Q/S, восстановление мгновенных функций и подготовка численных данных для векторных диаграмм**. Потенциальная диаграмма намеренно оставлена только для DC.

Формат `*.ecircuit.json` обновлён до версии `2`. Добавлены:

- `Analysis.Mode`;
- `Analysis.FrequencyHz`;
- `Elements[].PhaseDegrees`.

Файлы версии `1` сохраняют обратную совместимость и автоматически открываются в режиме DC.

## v10 — универсальные мощности, короткий трёхветвевой расчёт и векторные данные

Добавлено три независимых расширения общей установившейся модели DC/AC.

### Автоматическое упрощение трёхветвевой схемы

`ThreeBranchSimplifiedDetector` анализирует расчётный граф, а не координаты холста. Упрощение предлагается только для двухузловой схемы из трёх активных ветвей, где одна ветвь является питающей, а две другие — пассивными параллельными импедансами. Для AC используется комплексное правило деления токов; DC является вещественным частным случаем. В интерфейсе появляется отдельная карточка-предложение с кнопкой короткого расчёта.

### Комплексные мощности P/Q/S

`ComplexPowerCalculator` использует единое соглашение `S = U * conj(I)`. Для каждой ветви рассчитываются активная `P`, реактивная `Q` и полная (кажущаяся) `|S|` мощности. Пассивная мощность определяется через `|I|² Z`; мощность источников получается как остаток между пассивной и терминальной мощностью ветви, поэтому метод одинаково работает с источниками ЭДС и идеальными источниками тока. Баланс проверяется как комплексное равенство `ΣSист = ΣSпотр`. Для DC автоматически получается `Q=0`.

### Данные для векторных диаграмм

Новый режим «Данные для векторных диаграмм» доступен в AC. Он не рисует диаграмму, а выдаёт RMS-фазоры токов и напряжений в двух формах: алгебраической `a+jb` и показательной `M*e^(jφ)`. Дополнительно формируются напряжения отдельных R/L/C/источников, данные по каждому замкнутому контуру с проверкой второго закона Кирхгофа и токи каждого существенного узла с проверкой первого закона Кирхгофа.


## v11 — AC-законы Кирхгофа, комплексный МЭГ и мгновенные функции

### Законы Кирхгофа для AC

Режим «Законы Кирхгофа» теперь работает и для синусоидального установившегося режима. Первый закон записывается для комплексных RMS-фазоров токов `ΣI̲=0`. Во втором законе используются комплексные импедансы `ZR=R`, `ZL=jωL`, `ZC=1/(jωC)` и фазоры источников. Как и в DC, этот режим только формирует систему в общем виде и не выполняет численное решение.

### Метод эквивалентного генератора для AC

`EquivalentGeneratorSolver` получил общие настройки анализа и использует тот же интерфейс для DC/AC. В AC выбранная нагрузочная ветвь может содержать `R/L/C/E` и их последовательные сочетания; ветвь с идеальным источником тока `J` не поддерживается как нагрузка Тевенина. Последовательность решения сохранена учебной: разрыв → уравнение с `U̲хх` → МУП разомкнутой схемы → `U̲хх` → деактивация источников и тестовый ток → `Z̲вх` → `I̲н=(U̲хх−E̲н)/(Z̲вх+Z̲н)`. Результат автоматически сверяется с комплексным МУП полной исходной схемы.

### Восстановление мгновенных функций

Добавлен общий `InstantaneousWaveformFormatter`, не зависящий от конкретного решателя. Для фазора действующего значения `X̲=|X|∠φ` используется соглашение `x(t)=√2·|X|·sin(ωt+φ)`. Мгновенные функции токов и напряжений ветвей автоматически добавляются к результатам AC-МУП, AC-МКТ, AC-МЭГ, короткого трёхветвевого расчёта и режима данных для векторных диаграмм. Для независимых источников также выводятся заданные функции `e(t)`/`j(t)`.

Потенциальная диаграмма в AC не реализуется: в AC интерфейс блокирует этот режим и предлагает использовать векторные данные.

## Режим 3Φ (v12)

Добавлен отдельный установившийся трёхфазный режим. Источники задаются тремя обычными E (RMS + фаза) и назначаются A/B/C. Пассивные R/L/C также назначаются A/B/C; внутри каждой фазной/межфазной ветви допускается любое количество последовательных элементов. Для звезды A/B/C означают AN/BN/CN, для треугольника — AB/BC/CA. Поддерживаются звезда с нулевым проводом и с плавающей нейтралью, а также треугольник. Рассчитываются фазные/линейные токи, смещение нейтрали, P/Q/S и мгновенные функции. Модель не предполагает симметрию источника или нагрузки.
